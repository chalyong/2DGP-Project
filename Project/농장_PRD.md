# 농장(농사지) 시스템 개발 PRD

## 1. 문서 목적

이 문서는 `PRD.md` 4단계(농사지 시스템)와 `PRE_PRD2.md` 3장의 농사지 규칙을 기준으로, 농장 시스템의 개발 범위·구현 구조·완료 기준을 정리한 개발용 PRD다.

- 개발 환경: Python, `pico2d`
- 대상: 농사지 장면 전체 (맵, 재배, 성장, 상점, 농부 자동화)
- 선행 조건: `PRD.md` 0~3단계 완료 (게임 루프, 기본 맵·건물 입장, 자원/돈 데이터, 광산 시스템)
- 용어: 본 문서에서 농장은 기획서와 동일하게 **농사지**로 통일한다.

## 2. 기준 문서와 우선순위

1. `PRE_PRD2.md` 3장: 농사지 최신 세부 규칙
2. `PRD.md` 4단계: 구현 범위와 완료 기준
3. `SPRITE_PRD.md` 7장: 필요한 이미지 목록

문서 간 충돌 시 `PRE_PRD2.md`를 우선한다.

## 3. 핵심 규칙

### 3.1 시점과 맵 구조

- 농사지 입장 시 `top view`(상하좌우 방향키)로 전환한다. (기본 맵·광산은 좌우만 이동)
- 화면 **중앙 상단에 입구**를 배치하고, 입구에서 `Space`를 누르면 기본 맵으로 퇴장한다.
- **좌측 상단에 상인**을 배치해 농사지 상품을 판매한다.
- 재배 공간은 **우상단(재배 1)·좌하단(재배 2)·우하단(재배 3)** 3개 구역에 배치한다.

```text
  ㄴ상인     입구      재배 1ㄱ

             재배 2      재배 3」
```

### 3.2 재배 공간

- 각 재배 구역은 **5×5 칸**의 재배 공간을 제공한다 (총 3구역 75칸).
- 구역마다 **해금 상태**가 있으며, 해금된 구역에만 씨앗을 심는다.
- 각 구역 **중앙 칸에는 스프링클러**를 설치하고, 해당 칸은 **이동 불가**로 처리한다.
- 재배 칸(`crop_plot_tile`)과 잠긴 칸(`crop_plot_locked`)을 시각적으로 구분한다.

### 3.3 작물과 성장

| 작물 | 자원 키 | 성장 단계 | 상태 |
| --- | --- | --- | --- |
| 밀 | `wheat` | seed → sprout → growing → ready | 기본 해금 |
| 감자 | `potato` | 동일 4단계 | 해금 상품으로 구매 |
| 딸기 | `strawberry` | 동일 4단계 | 해금 상품으로 구매 (순서는 개발 중 결정) |

- 씨앗을 심으면 `seed`부터 시작해 시간에 따라 단계가 진행된다.
- **수확 후 2분**이 지나면 칸이 다시 작물을 품는다(재성장).
- `ready` 상태의 칸 위에서 `Space`를 누르면 수확한다.
- 수확하면 `game_state.collected_items`의 해당 자원 수량이 증가한다.
- 심기·수확은 **현재 칸에 서 있을 때만** 동작하며, 이동 중에는 무시한다.

### 3.4 농사지 상점

| 상품 | 기능 | 구매 방식 |
| --- | --- | --- |
| 괭이 (`hoe`) | 수확 시 획득량 증가 (단계별 업그레이드) | 돈 |
| 비료 (`fertilizer`) | 성장에 필요한 시간 감소 | 돈 (소모품 여부는 개발 중 결정) |
| 작물 2 해금 | 해당 작물의 재배 구역/씨앗 해금 | 돈 + 선행 조건 |

- 상점 UI는 광산 상점(`shop.py`)의 페이지/클릭 구조를 재사용한다.
- 구매 결과는 `game_state`에 기록되며 인벤토리에 표시한다.

### 3.5 농부 자동화 (8단계와 연결)

- 농부는 고용한 재배 구역에서 **무작위로 이동하며 발밑의 ready 작물을 자동 수확**한다.
- 농부의 이동 속도는 **플레이어 속도를 기반**으로 계산한다 (4절 속도 기준 참조).
- 농부는 구역별로 **최대 3명**까지 고용한다.
- 농부의 수확량은 플레이어가 보유한 **괭이 효율의 영향**을 받는다.
- 고용 비용과 자동 수확 주기는 개발 중 결정한다.

## 4. 데이터 구조

`game_state.py`에 농사지 상태를 추가한다. 광산의 `miners` / `passes`와 같은 패턴으로 관리한다.

```python
# 예시 — 이름과 세부 값은 구현 시 조정
farm_plots = {           # 재배 구역 해금 상태
    "wheat": True,       # 구역 1 (기본 해금)
    "potato": False,
    "strawberry": False,
}
crop_slots = []          # (구역, 칸 x, 칸 y, 작물, 단계, 상태 시각)
farm_tools = []          # 보유 괭이·비료
farmer_count = {"wheat": 0, "potato": 0, "strawberry": 0}
```

- 자원 수량은 기존 `collected_items`를 그대로 사용한다 (`wheat`, `potato`, `strawberry` 키 추가).
- 성장·재성장은 `pico2d.get_time()` 기반 경과 시간으로 계산한다. 프레임 수에 의존하지 않는다. (광산 시스템과 동일한 패턴)
- **속도 기준**: 자동 NPC(농부·관리인 등)의 이동량 계산은 `player.py`의 **플레이어 속도를 기반**으로 한다. 같은 단위·같은 시간 기준으로 환산해 사용하고, **동물의 속도는 그 절반**으로 잡는다. 플레이어 속도가 조정되면 자동 NPC 속도도 함께 따라간다.
- 미정 수치(성장 시간, 해금 순서, 효율)는 한 곳에 모아 조정할 수 있게 상수로 관리한다.

전체 예상 커밋 수: **약 22개** (F1~F5 19 + 마무리 3).

**규칙**

1. **커밋 단위 표를 따른다** — 한 커밋에는 한 가지 변경만 담고, 여러 단계를 섞지 않는다. 커밋 메시지에 어느 단계의 작업인지 접두어로 남긴다.
2. **커밋 전 검증** — 해당 단계의 완료 기준 체크리스트를 통과하고, 게임 실행(`python main.py`)과 기존 광산 시스템 동작을 확인한 뒤 커밋한다.
3. **실패한 작업은 커밋하지 않는다** — 동작하지 않는 중간 상태 대신 되돌리고, 다음 시도와 함께 다시 쌓는다.
4. **PRD와 코드를 함께 갱신한다** — 구현 중 규칙이 바뀌면 `농장_PRD.md`의 해당 섹션을 같은 커밋에서 수정해 문서와 구현이 어긋나지 않게 한다.
5. **새 이미지 추가 시에는 에셋과 로딩 코드를 함께 커밋한다** — 로드 경로가 깨진 상태(`FileNotFoundError`)로 커밋하지 않는다.
6. 커밋 메시지는 영문 소문자+접두어(`f1:` ~ `f5:`, `fix:`, `tune:`)로 시작해 한 줄로 요약한다.

**분기 관리**

- 농장 작업은 별도 브랜치(`feature/farm`)에서 진행하고, 각 F 단계 완료 시점에 메인 브랜치로 머지한다.
- 광산 시스템(`shop.py`, `game_state.py`, `inventory.py`)과 농장이 같은 파일을 수정해야 하는 경우, 공통 부분(상점 구조, 자원 데이터)은 먼저 반영해 두고 농장 전용 코드는 브랜치에서 작업한다.

### F1. 농사지 맵과 입장·퇴장

**구현 내용**

- `top view` 농사지 배경 표시 (`farm_background.png`)
- 플레이어 **4방향 이동** 지원 (기존 좌우 이동 확장 — `player.py`의 이동 처리를 상하로 확장)
- 입구·상인 배치와 `Space` 퇴장 판정
- 상인과의 상호작용 범위 판정 (광산 상인 방식)
- 카메라 경계: 농사지 화면 범위를 벗어나지 않도록 제한

**완료 기준**

- 기본 맵에서 농사지 입장/퇴장이 정상 동작한다.
- 상하좌우 이동이 되고 화면 밖으로 나가지 않는다.
- 상인 앞에서 상점을 열고 닫을 수 있다.

### F2. 재배 구역과 씨앗 심기

**구현 내용**

- 3개 재배 구역(5×5)의 칸 데이터와 시트 렌더링 (`crop_plot_tile`, `crop_plot_locked`)
- 해금 상태에 따라 잠긴 칸/심기 가능 칸 표시
- 스프링클러 설치 칸과 **이동 충돌 처리**
- 칸 위에서 `Space`로 씨앗 심기 (해금 구역만)
- 인벤토리의 자원/도구 탭과 연동

**완료 기준**

- 해금된 구역에만 작물을 심을 수 있다.
- 스프링클러 칸으로는 이동할 수 없다.
- 심은 칸과 빈 칸, 잠긴 칸이 시각적으로 구분된다.

### F3. 성장·수확·재성장

**구현 내용**

- 4단계 성장 처리 (경과 시간 기반, `get_time()` 사용)
- `ready` 칸에서 `Space` 수확 + 획득량 알림 (광산 채굴 알림과 동일 연출)
- 수확 후 2분 재성장
- 괭이별 수확 획득량 처리 (`mining_yield`와 유사한 `harvest_yield` 함수)
- 비료의 성장 시간 단축 적용

**완료 기준**

- 수확 성공 시 올바른 자원이 정확한 양으로 지급된다.
- 수확 후 성장 시간이 지나면 다시 수확할 수 있다.
- 보유 수량이 음수가 되지 않는다.
- 성장 진행이 프레임/성능과 무관하게 일정한 속도로 진행된다.

### F4. 농사지 상점

**구현 내용**

- 상점 UI (광산 `shop.py`의 모드/페이지 구조 재사용)
- 괭이 구매와 획득량 업그레이드 반영
- 비료 구매와 성장 시간 단축 반영
- 작물 해금 상품 (선행 조건 + 가격 검증)
- 구매 결과 메시지와 잔액/재료 검증 (광산 상점과 동일 규칙)

**완료 기준**

- 조건이 충족되지 않으면 구매가 거부되고 사유가 표시된다.
- 구매 후 해당 기능이 즉시 적용된다.
- 중복 구매가 차단된다.

### F5. 농부 자동 수확

**구현 내용**

- 농부 고용 UI와 구역별 3명 제한
- 농부 스프라이트 배치와 무작위 이동 (`farmer_idle/walk/harvest`)
- 발밑 `ready` 작물 자동 수확과 주기 처리
- 괭이 효율이 농부 수확량에 반영
- 광부와 동일한 방식의 전역 주기 타이머 (농사지 밖에 있어도 진행)

**완료 기준**

- 고용한 구역에서만 자동 수확이 동작한다.
- 구역당 3명을 초과해 고용할 수 없다.
- 자동화 중 자원·돈 수량이 정확하다.

## 6. 완료 기준 (PRD.md 4단계 요약)

- 해금된 재배 공간에만 작물을 심을 수 있다.
- `Space` 키로 작물을 수확할 수 있다.
- 수확 후 성장 시간이 지나면 다시 수확할 수 있다.
- 작물 수확량과 재고가 정상적으로 갱신된다.

## 7. 개발 중 결정 사항

- 농작물 해금 순서와 해금 조건
- 성장 시간 (기준 2분), 비료 단축 비율
- 괭이 단계별 획득량 증가폭과 가격
- 농부 고용 비용과 자동 수확 주기
- 씨앗 가격과 작물별 판매가 (광산 판매 페이지 패턴 참고)
- 비료의 소모품/영구 업그레이드 여부
