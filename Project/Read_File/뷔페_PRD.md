# 뷔페 PRD

> **대상**: 뷔페 시스템 (6~7단계)
> **상태**: 6단계 사전 준비. 시스템·UI는 미구현, 요리 데이터와 COOKING 탑재는 임시 구현
> **목적**: 주방·식탁·의자·요리사의 규칙을 확정해 6단계 개발의 기준으로 삼는다 (손님 동선은 7단계)

---

## 1. 목적

- 농사·목장·광산 자원을 요리로 전환하고, 손님에게 판매해 수익을 만든다.
- 시설(식탁·의자·장식) 성장 곡선을 제공한다.
- 플레이어의 자동화 농사·목장·광산의 최종 소비처 역할을 한다.

---

## 2. 범위

손님 동선·응대 규칙은 손님 단계(7단계)에서 별도 작성한다.

| 항목                 | 포함                                              | 제외                                       |
| -------------------- | ------------------------------------------------- | ------------------------------------------ |
| 뷔페 `top view` 맵 | 입구·계산대·상점·요리사·요리 공간·식탁·의자 | 기본 맵 자체 개편                          |
| 시설 상점            | 식탁·의자·장식 구매/업그레이드                  | 자원·동물·도구 판매(기존 상점 담당)      |
| 요리 제작            | 요리사 상호작용 제작(임시: COOKING 탭)            | 광물(시설 재료로만 사용)                   |
| 손님 동선·응대      | (7단계에서 별도 작성)                             | 기본 맵 NPC(농부·광부·관리인), 자동 응대 |

---

## 3. 게임플레이

### 3.1 뷔페 구조

- 뷔페는 `top view`로 구성한다.
- 입구는 **하단 중앙**에 배치한다.
- 이미지 제작에 사용했던 내용을 기반으로 맵을 다시 구성한다.

```text
[최상단] 벽 (장식용 선반·시계 등)
┌────────────────────────────────────────────┐
│  주방 (KITCHEN) — 화면 위 ~2/5            │
│  조리대·오븐·후드 자리 (주방 오브젝트 별도)  │
│  요리사                                   │
│  요리1   요리2   요리3   요리4   요리5 …   │
├────────────────────────────────────────────┤
│  계산대 (COUNTER) — 화면 중앙 ~1/5        │
│  왼쪽 벽을 따라 긴 카운터 자리 (별도 오브젝트)│
│  상호작용 공간 여백 (포스기·금고 자리)       │
│                          상인(시설 상점)    │
├────────────────────────────────────────────┤
│  식사 공간 (DINING) — 화면 아래 ~2/5      │
│  식탁 자리(별도 오브젝트) + 의자 배치 여백    │
│  창문·식물 등 장식 요소                     │
└────────────────────────────────────────────┘
[하단] 입구 출입문 (가운데)
```

- 구역마다 바닥 색이 확실히 달라야 한다 (식사=갈색 나무, 카운터=회색 타일, 주방=밝은 회색).
- 식탁·의자·계산대·조리대는 별도 이미지 오브젝트이므로 배경에는 그리지 않는다 (자리 표시만).
- 구역 안쪽은 오브젝트를 얹을 여백으로 비워둔다.
- 계산대 위쪽/아래쪽 `Space` 상호작용(입장·결제)은 손님 단계(7단계)에서 구현한다.

### 3.2 시설 상점과 구매 규칙

- 상인은 시설 업그레이드 관련 아이템만 판매한다.
- 자원·동물·도구는 기존 상점(광산/농장/목장)에서 판매한다.

#### 식탁·의자 구매 규칙

- 식탁과 의자는 뷔페 상점에서 구매한다.
- 다음 식탁을 구매하려면 **의자 2개를 먼저 구매**해야 한다.
- 여유 식탁이 없으면 의자를 구매할 수 없다.

| 항목            | 비용 또는 재료 | 효과                                   |
| --------------- | -------------- | -------------------------------------- |
| 의자 업그레이드 | 광물 × n개    | 손님이 오래 머무를 확률 증가           |
| 식탁 업그레이드 | 추후 결정      | 손님의 식사 속도 증가                  |
| 장식 업그레이드 | 추후 결정      | 결제 금액 증가, 손님 입장 확률 증가 등 |

### 3.3 요리사와 요리 제작

- 요리사는 요리 제작에 필요한 재료를 요구한다.
- 플레이어는 요리사와 상호작용해 요리별 제작 메뉴를 확인한다.
- 요리 제작 버튼은 뷔페 상점이 아닌 **요리사에게** 제공한다.
- 재료가 충분한 요리만 제작 요청할 수 있다.

#### 제작 방식 — 수량 설정 후 리듬게임

- 요리사에게서 원하는 요리를 선택해 **제작 수량을 설정**한다 (-1, +1, max 버튼, 하단 제작 버튼).
- 여러 음식의 수량을 동시에 설정할 수 있다.
- 제작을 요청하면 **반투명한 4노트 리듬게임 판**이 화면에 나타난다.
- 요청한 음식들이 랜덤한 순서로 위에서 내려온다 (등장 간격 최소 0.5초~최대 1초, 동시에 최대 2개).
- 리듬게임에 **성공한 개수만큼 요리를 획득**한다. 정확한 타이밍에 누르면 2개씩 제작된다. / 판정 
- 제작에 성공한 만큼 요리가 요리 공간에 생성된다.
- 제작한 요리는 손님이 뷔페에서 선택해 먹는다 (선택·소비 처리는 손님 단계).

#### 요리 목록

기본 판매가를, 재료를 그냥 팔았을 때에 비해, 업그레이드가 없을 때 기준, 약 10% 정도의 이득이 나도록 설계한다. 요리는 전부 **상시 해금**이다.

| 단계 | 요리          | 재료            | 판매가 |
| ---- | ------------- | --------------- | ------ |
| 초반 | 감자튀김      | 감자 1          | $40    |
| 초반 | 계란빵        | 밀 1 + 달걀 1   | $60    |
| 초반 | 딸기 디저트   | 딸기 1 + 우유 1 | $90    |
| 중반 | 버섯 수프     | 버섯 1 + 우유 1 | $80    |
| 후반 | 고기 스테이크 | 고기 1 + 감자 1 | $200   |

- 판매가 기준은 현재 `game_state.RECIPES`의 기본값이며 조정 가능하다.
- 고기 스테이크의 "고기"는 닭고기·소고기·돼지고기 중 어느 것이든 1개 소비한다.
- 광물은 요리 재료가 아니라 주방 시설, 식탁, 의자, 장식 업그레이드에 사용한다.

### 3.4 손님 동선과 응대 (7단계에서 작성)

- 손님 동선(입장·대기·선택·식사·결제·퇴장)과 입장/결제 `Space` 처리 규칙은 손님 단계에서 확정해 별도 작성한다.
- 지금은 뷔페의 기능(맵·시설 상점·요리 제작)만 구현한다.

#### 6단계 완료 기준

- 뷔페 상인은 시설 업그레이드만 판매한다.
- 식탁 구매 전 의자 2개, 의자 구매 전 여유 식탁 규칙이 적용된다.
- 요리사에게서 수량을 설정해 제작을 요청할 수 있다.
- 4노트 리듬게임에서 성공한 개수만큼 요리가 요리 공간에 생성된다.
- 재료가 부족할 때 제작되지 않으며 오류 상태가 표시된다.

#### 7단계 완료 기준 (손님 단계에서 확정)

- 손님은 입장부터 퇴장까지 순서대로 상태가 바뀐다.
- 손님이 요리를 선택하면 요리 재고가 감소한다.
- 대기 줄과 식탁이 가득 찬 상황을 처리한다.
- 플레이어가 입장(`Space` 상단)과 결제(`Space` 하단)를 처리할 수 있다.

| 항목                | 상태           | 비고                                                                                                 |
| ------------------- | -------------- | ---------------------------------------------------------------------------------------------------- |
| 뷔페 맵             | ❌ 미구현      | 6단계에서 구축                                                                                       |
| 시설 상점           | ❌ 미구현      | 식탁·의자·장식 데이터는 6단계에서 정의                                                             |
| 요리사 제작         | ⚠️ 임시 구현 | 인벤토리 COOKING 탭 클릭 제작 (`RECIPES`/`cook()`), 6단계에서 요리사 상호작용(리듬게임)으로 이관 |
| 손님 동선           | ❌ 미구현      | 7단계 (규칙도 그때 작성)                                                                             |
| 입장/결제 `Space` | ❌ 미구현      | 7단계                                                                                                |

## 5. 결정 사항

1. **top view 뷔페**, **하단 중앙 입구**, 식사 공간(하단) → 계산대(중앙) → 주방(상단) 순으로 배치.
2. 식탁 구매 전 **의자 2개 필수**, 의자 구매 전 **여유 식탁** 필요.
3. 제작은 **요리사**에게, 구매는 **상인**에게 — 상점/제작 분리. 제작은 수량 설정 후 **4노트 리듬게임**으로 진행한다.
4. 5종 요리(감자튀김·계란빵·딸기 디저트·버섯 수프·고기 스테이크)는 **상시 해금**, 판매가 $40/60/90/80/200.
5. **임시 구현**: 뷔페 맵이 나오기 전까지 인벤토리 COOKING 탭에서 제작, 6단계에서 요리사로 이관.
6. 광물은 요리 재료가 아니라 **시설 업그레이드 재료**로만 사용한다.

## 6. 점진적 커밋 진행 계획 (6단계)

6단계는 아래 순서대로 **작은 커밋 단위**로 진행한다.

- 각 커밋은 스모크 테스트 통과 후 커밋한다.
- 규칙이 바뀌면 코드와 **같은 커밋에서 PRD를 함께 갱신**한다.
- 커밋 접두사는 농장 `f`·목장 `r`에 이어 **`b`**를 사용한다.

| 순서 | 접두사  | 내용        | 완료 기준                                                       |
| ---- | ------- | ----------- | --------------------------------------------------------------- |
| 1    | `b1:`   | 뷔페 맵 구축 | top view 배경(주방·계산대·식사공간 3구역 바닥색), 하단 중앙 입구, 장면 진입/퇴장 |
| 2    | `b2:`   | 시설 상점   | 식탁·의자·장식 데이터와 구매 UI, 선행 규칙(식탁=의자 2개 선행, 의자=여유 식탁 필요) |
| 3    | `b3:`   | 요리사 제작 UI | 요리사 상호작용 메뉴, 수량 설정(-1/+1/max), 하단 제작 버튼, 재료 부족 오류 표시 |
| 4    | `b4:`   | 4노트 리듬게임 | 반투명 판, 노트 낙하(0.5~1초 간격·동시 최대 2개), 성공 수량만큼 생성, 정확 타이밍 2개 |
| 5    | `b5:`   | 요리 공간 배치 | 제작 성공분이 요리 공간에 표시되고 재고가 관리된다              |
| 6    | `b6:`   | 임시 구현 정리 | COOKING 임시 탭과의 공존/제거 결정, 진행 상태표 갱신            |

- 손님 동선·입장/결제 `Space`(7단계)는 이 계획에서 제외한다.
