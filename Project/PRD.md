# HARVEST TABLE 개발용 PRD

## 1. 문서 목적

이 문서는 `PRE_PRD.md`, `PRE_PRD2.md`, `발표_PRD.md`, `기획_PRD.md`를 바탕으로 실제 개발 순서와 구현 기준을 정리한 개발용 PRD다.

- 개발 환경: Python, `pico2d`
- 장르: 2D 타이쿤·경영 게임
- 핵심 구조: 자원 채집 → 요리 제작·시설 확장 → 뷔페 운영 → 수익 획득 → 자동화
- 최종 목표: 요리 5종을 각각 100개 이상 판매하고, 개발 중 결정한 최종 보유 금액 조건을 달성한다.
- 미정 수치와 세부 규칙은 구현과 플레이 테스트 과정에서 결정한다.

## 2. 기준 문서와 적용 우선순위

문서 간 내용이 다를 경우 다음 우선순위를 적용한다.

1. `PRE_PRD2.md`: 실제 게임 기능과 최신 세부 규칙
2. `기획_PRD.md`: 제출용 기능 범위와 시스템 구성
3. `PRE_PRD.md`: 초기 콘셉트, 핵심 재미, 개발 규모
4. `발표_PRD.md`: 초기 발표용 요약과 단계별 개발 방향

최신 상세 기획에 따라 다음 내용을 사용한다.

- 농장이라는 표현은 `농사지`로 통일한다.
- 광물은 석탄·철·금이다.
- 농작물은 밀·감자·딸기다.
- 목장 자원은 달걀·우유·버섯이며, 사냥용 칼을 사용하면 고기를 얻을 수 있다.
- 요리사는 요리를 제작하고, 뷔페 상인은 시설 업그레이드만 판매한다.
- 저장 슬롯은 5개다.
- 엔딩은 요리 5종 판매량과 최종 보유 금액 조건을 사용한다. 보유 금액은 개발 중 결정한다.

## 3. 핵심 게임 루프

```text
기본 맵 이동
  ↓
광산·농사지·목장에서 자원 획득
  ↓
자원 판매·요리 제작·시설 업그레이드
  ↓
뷔페에 요리 배치
  ↓
손님 입장·식사·결제
  ↓
수익으로 장비·시설·직원 확장
  ↓
채집·생산·손님 응대 자동화
```

## 4. 공통 규칙

### 4.1 기본 맵

- 맵은 좌우로 길게 구성하며 카메라가 플레이어를 따라 스크롤한다.
- 건물은 다음 순서로 배치한다.

```text
집 → 농사지 → 목장 → 광산 → 뷔페
```

- 기본 맵에서는 좌우 방향키로 이동한다.
- 건물 앞에서 `Space` 키를 누르면 입장한다.

### 4.2 건물별 시점

| 공간 | 시점 | 이동 |
| --- | --- | --- |
| 기본 맵 | 횡스크롤 | 좌우 방향키 |
| 광산 | `front view` | 좌우 방향키 |
| 농사지 | `top view` | 상하좌우 방향키 |
| 목장 | `top view` | 상하좌우 방향키 |
| 뷔페 | `top view` | 상하좌우 방향키 |

- 건물 내부 입구에서 `Space` 키를 누르면 기본 맵으로 돌아간다.

## 5. 개발 순서

각 단계는 앞 단계의 기본 기능이 동작한 뒤 진행한다. 단계별 완료 조건을 만족하면 다음 단계로 넘어간다.

### 0단계. 프로젝트 기반과 공통 데이터

**구현 내용**

- `pico2d` 실행 창과 게임 루프 구성
- 입력 처리와 프레임 갱신
- 장면 전환 구조
- 플레이어, 아이템, 돈, 시간 데이터를 관리하는 기본 자료 구조
- 공통 충돌 및 상호작용 판정

**완료 기준**

- 게임을 실행하고 종료할 수 있다.
- 방향키 입력과 `Space` 입력을 구분할 수 있다.
- 테스트용 장면을 열고 닫을 수 있다.

### 1단계. 기본 맵과 건물 입장

**구현 내용**

- 기본 맵 배경과 건물 배치
- 플레이어 좌우 이동
- 카메라 스크롤
- 건물 앞 상호작용 영역
- 집·농사지·목장·광산·뷔페 장면 입장과 퇴장

**완료 기준**

- 건물 배치 순서가 기획과 일치한다.
- 플레이어가 각 건물에 입장하고 기본 맵으로 돌아올 수 있다.
- 화면 밖으로 이동할 수 없다.

### 2단계. 자원과 기본 재화

**구현 내용**

- 석탄·철·금, 밀·감자·딸기, 달걀·우유·버섯·고기 데이터
- 돈과 자원 수량 변경
- 자원 획득·소비·판매 처리
- 화면에 자원과 돈을 표시하는 기본 UI

**완료 기준**

- 자원을 획득하면 수량이 증가한다.
- 판매와 소비 후 수량이 정확히 감소한다.
- 보유 수량이 음수가 되지 않는다.

### 3단계. 광산 시스템

**구현 내용**

- 광산 외부의 출입구·상인·땅굴 배치
- 석탄·철·금 순서의 땅굴 구성
- 해금된 땅굴과 잠긴 땅굴 표시
- 땅굴 내부의 입구·채굴 공간·광부 배치
- `Space` 키를 이용한 수동 채굴
- 나무·돌·철 곡괭이와 채굴량 처리
- 광산 상점

**완료 기준**

- 해금된 땅굴에만 입장할 수 있다.
- 채굴 성공 시 올바른 광물이 지급된다.
- 곡괭이에 따라 채굴 가능한 광물과 획득량이 달라진다.
- 채굴 성공 확률은 개발 중 결정한 값으로 적용된다.

### 4단계. 농사지 시스템

**구현 내용**

- `top view` 농사지 맵과 입구·상점 배치
- 작물별 5×5 재배 공간
- 중앙 스프링클러와 이동 제한
- 밀·감자·딸기 재배 및 수확
- 수확 후 성장 시간
- 괭이·비료·작물 해금 상점

**완료 기준**

- 해금된 재배 공간에만 작물을 심을 수 있다.
- `Space` 키로 작물을 수확할 수 있다.
- 수확 후 성장 시간이 지나면 다시 수확할 수 있다.
- 작물 수확량과 재고가 정상적으로 갱신된다.

### 5단계. 목장 시스템

**구현 내용**

- 닭·소·돼지 울타리 구역
- 동물 배치와 이동
- 달걀·우유·버섯 획득
- 자원 재획득 시간
- 동물 판매와 교배
- 사냥용 칼 구매 및 고기 획득

**완료 기준**

- 동물 구역별로 올바른 자원을 얻는다.
- 자원 재획득 전에는 중복 획득할 수 없다.
- 사냥용 칼 사용 시 칼과 동물이 각각 1개씩 감소한다.
- 교배 조건을 충족하면 동물이 추가된다.

### 6단계. 뷔페 시설과 요리 제작

**구현 내용**

- 뷔페 `top view` 맵
- 입구·계산대·상점·요리사·요리 공간
- 식탁·의자 구매 규칙
- 의자 2개 구매 후 다음 식탁 구매 가능
- 요리사 상호작용과 제작 메뉴
- 다음 5종 요리 제작

| 요리 | 재료 |
| --- | --- |
| 감자튀김 | 감자 |
| 계란빵 | 밀, 달걀 |
| 딸기 디저트 | 딸기, 우유 |
| 버섯 수프 | 버섯, 우유 |
| 고기 스테이크 | 고기, 감자 |

**완료 기준**

- 뷔페 상인은 시설 업그레이드만 판매한다.
- 요리사는 재료가 충분할 때 요리를 즉시 제작한다.
- 제작한 요리가 요리 공간에 생성된다.
- 재료가 부족할 때 제작되지 않으며 오류 상태가 표시된다.

### 7단계. 손님 이동과 뷔페 운영

**구현 내용**

- 기본 맵 외곽에서 손님 생성
- 일정 확률의 뷔페 입장
- 입장 대기 줄과 계산대 위쪽 상호작용
- 요리 선택과 식탁 이동
- 무작위 횟수의 추가 요리 이용
- 결제 줄과 계산대 아래쪽 상호작용
- 계산 후 입구를 통한 퇴장

**동선**

```text
입구 → 입장 대기 줄 → 계산대 → 요리 선택 → 식탁
식탁 → 결제 줄 → 계산대 → 입구 → 기본 맵 퇴장
```

**완료 기준**

- 손님이 입장부터 퇴장까지 순서대로 상태를 변경한다.
- 플레이어가 입장 처리와 계산 처리를 할 수 있다.
- 손님이 요리를 선택하고 요리 재고가 감소한다.
- 대기 줄과 식탁이 가득 찬 상황을 처리한다.

### 8단계. 업그레이드와 자동화

**구현 내용**

- 곡괭이·괭이·비료 업그레이드
- 땅굴·작물 구역 해금
- 광부의 자동 채굴
- 농부의 자동 수확
- 관리인의 목장 자동 수확
- 직원의 손님 응대·계산 자동화
- 시설 및 장식 업그레이드

**개발 순서**

1. 수동 작업의 보상과 소비를 먼저 안정화한다.
2. 동일 작업을 수행하는 자동화 담당자를 추가한다.
3. 작업 주기와 비용을 적용한다.
4. 수동 작업과 자동 작업의 효율을 비교해 조정한다.

**완료 기준**

- 직원을 고용하면 담당 작업이 자동으로 실행된다.
- 자동화 중에도 자원·요리·돈의 수량이 정확하다.
- 자동화 효율과 고용 비용은 개발 중 결정한 값으로 조정 가능하다.

### 9단계. 저장 및 불러오기

**구현 내용**

- 집 앞 저장·불러오기 메뉴
- 저장 이름 입력
- 5개 저장 슬롯
- 저장 목록 표시
- 슬롯이 가득 찼을 때 기존 저장 삭제 후 새 저장
- 맵 진행도, 자원, 돈, 시설, 직원, 통계 저장

**완료 기준**

- 저장 후 게임을 종료해도 데이터가 유지된다.
- 저장 데이터를 불러오면 저장 시점의 상태가 복원된다.
- 슬롯 초과 시 사용자가 삭제할 저장을 선택할 수 있다.
- 잘못된 저장 데이터는 성공한 것처럼 처리하지 않고 오류를 표시한다.

### 10단계. 엔딩과 결과 화면

**구현 내용**

- 요리 5종별 판매량 집계
- 최종 보유 금액 집계
- 엔딩 조건 판정
- 완료 화면
- 플레이 시간·광산 채집량·농작물 수확량·목장 자원 획득량·직원 수·분당 수익 표시

**엔딩 조건**

- 요리 5종을 각각 100개 이상 판매한다.
- 개발 중 결정한 기준 금액 이상을 보유한다.

**완료 기준**

- 조건을 모두 충족할 때만 엔딩이 발생한다.
- 결과 화면에 실제 플레이 통계가 표시된다.
- 엔딩 이후 결과 화면에서 게임을 종료하거나 다시 시작할 수 있다.

### 11단계. 통합 테스트와 밸런스 조정

**검증 내용**

- 기본 맵에서 엔딩까지 전체 흐름 테스트
- 자원 획득·소비·판매 수량 검증
- 손님 입장·식사·결제·퇴장 검증
- 자동화 전환 검증
- 저장·불러오기와 슬롯 초과 검증
- 엔딩 조건 및 결과 통계 검증
- 가격, 해금 조건, 성공 확률, 성장 시간, 손님 행동 시간 조정

**완료 기준**

- 핵심 구현 범위의 모든 완료 기준을 통과한다.
- 치명적인 진행 불가 오류가 없다.
- 실제 완성 가능한 콘텐츠 규모로 제한되어 있다.
- 제출용 실행본과 개발 문서가 현재 구현 상태와 일치한다.

## 6. 개발 중 결정 사항

다음 항목은 기능 구현 후 테스트를 통해 확정한다.

- 아이템·업그레이드·직원·관리인 고용 비용
- 땅굴과 농작물 해금 조건
- 광산 채굴 성공 확률
- 농부·관리인·광부의 작업 주기와 효율
- 작물과 목장 자원의 재획득 시간
- 손님 입장 확률과 행동 시간
- 요리별 판매 가격·만족도·수익 차이
- 식탁·장식 업그레이드 효과
- 엔딩에 필요한 보유 금액
- 분당 수익 계산 기준
- 저장 파일 형식과 저장 데이터 세부 변수
- 결과 화면의 세부 디자인

## 7. 개발 우선순위 원칙

- 플레이어가 직접 조작하는 핵심 흐름을 자동화보다 먼저 구현한다.
- 자원과 돈의 수량 처리를 공통 데이터로 관리해 시스템별 중복을 줄인다.
- 각 단계의 완료 기준을 통과한 뒤 다음 시스템을 추가한다.
- 미정 수치는 코드에 흩어 놓지 않고 한 곳에서 조정할 수 있도록 관리한다.
- 오류나 저장 실패를 성공한 것처럼 처리하지 않고 사용자에게 표시한다.
- 초기 구현 범위를 벗어나는 장식·추가 메뉴·확장 시설은 핵심 기능 완료 후 진행한다.

## 8. 최종 제출 기준

- 게임 실행과 종료가 정상 동작한다.
- 기본 맵에서 모든 핵심 건물에 입장할 수 있다.
- 자원 채집, 요리 제작, 뷔페 운영, 수익 획득이 연결된다.
- 수동 운영에서 자동화로 발전하는 흐름이 동작한다.
