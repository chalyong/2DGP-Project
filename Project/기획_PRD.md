# 제출용 게임 기획 PPT 제작 요구사항

## 1. 문서 목적

- 실제 게임 기능 기획서인 `PRE_PRD2.md`를 바탕으로 제출용 기획 PPT를 제작한다.
- 게임의 전체 구조, 핵심 플레이, 성장 방식, 구현 범위를 문서 형태로 정리한다.
- 아직 확정되지 않은 수치와 세부 규칙은 **개발 중 결정**으로 표기한다.
- PPT 분량은 약 3~50페이지 범위에서 목적과 내용에 맞게 자유롭게 구성한다.
- 페이지 수를 채우는 것은 목표가 아니며, 필요한 내용만 작성한다.
- 현재 기획 기준 권장 분량은 약 14페이지로 구성한다.

## 2. 게임 기본 정보

- 장르: 2D 타이쿤·경영 게임
- 개발 환경: Python, `pico2d`
- 게임 방식: 자원 채집, 시설 운영, 요리 제작, 손님 응대, 자동화
- 목표: 요리 5종을 각각 100개 이상 판매
- 핵심 재미: 직접 운영하던 작업이 점차 자동화되는 성장 과정

## 3. 권장 PPT 구성

### 약 14페이지 구성

#### 1페이지. 표지

- 게임 제목
- 장르: 2D 타이쿤·경영 게임
- 개발 환경: Python, `pico2d`
- 이름과 학번

#### 2페이지. 게임 개요

- 플레이어가 운영하는 게임의 전체 콘셉트
- 기본 맵에 배치된 건물
  - 집
  - 농사지
  - 목장
  - 광산
  - 뷔페
- 게임의 최종 목표

#### 3페이지. 전체 게임 흐름

다음 순환 구조를 흐름도로 표현한다.

```text
자원 채집
  ↓
자원 판매·요리 제작·시설 업그레이드
  ↓
뷔페 운영 및 손님 응대
  ↓
수익 획득
  ↓
채집·생산·응대 자동화
```

#### 4페이지. 기본 맵과 조작

- 좌우로 긴 기본 맵과 카메라 스크롤
- 건물 배치 순서
- 좌우 방향키 이동
- 건물 앞 `Space` 키 입장
- 건물별 시점
  - 광산: 정면 시점
  - 농사지·목장·뷔페: `top view`

#### 5페이지. 광산 시스템

- 광산 외부와 땅굴 구조
- 석탄, 철, 금의 자원 단계
- 땅굴 해금 방식
- 플레이어의 수동 채굴
- 광부의 자동 채굴
- 곡괭이 업그레이드

광산의 구조는 다음과 같이 표현한다.

```text
출입구 → 상인 → 땅굴1 → 땅굴2 → 땅굴3
```

#### 6페이지. 농사지 시스템

- `top view` 기반 농사지 구조
- 밀, 감자, 딸기 재배
- 5×5 재배 공간
- 스프링클러와 이동 제한
- `Space` 키를 이용한 수확
- 괭이와 비료
- 농부를 통한 자동 수확

#### 7페이지. 목장 시스템

- 울타리로 구분된 동물 구역
- 닭, 소, 돼지 배치
- 달걀, 우유, 버섯 획득
- 동물 판매와 교배
- 관리인의 자동 수확
- 사냥용 칼을 이용한 고기 획득

#### 8페이지. 뷔페 구조와 시설

- `top view` 기반 뷔페 배치
- 입구와 계산대
- 입장 손님과 결제 손님 대기 줄
- 식탁과 의자 구매 규칙
- 장식 및 시설 업그레이드

식탁과 의자 규칙을 다음과 같이 설명한다.

- 식탁과 의자는 뷔페 상점에서 구매한다.
- 다음 식탁을 구매하려면 의자 2개를 먼저 구매해야 한다.
- 여유 식탁이 없으면 의자를 구매할 수 없다.

#### 9페이지. 요리사와 요리 제작

- 요리 관련 기능은 뷔페 상인이 아닌 요리사가 담당한다.
- 요리사와 상호작용해 제작 메뉴를 확인한다.
- 재료가 충분하면 요리를 즉시 제작한다.
- 제작한 요리는 요리 공간에 배치된다.
- 손님이 요리를 선택해 먹는다.

| 단계 | 요리 | 재료 |
| --- | --- | --- |
| 초반 | 감자튀김 | 감자 |
| 초반 | 계란빵 | 밀, 달걀 |
| 초반 | 딸기 디저트 | 딸기, 우유 |
| 중반 | 버섯 수프 | 버섯, 우유 |
| 후반 | 고기 스테이크 | 고기, 감자 |

#### 10페이지. 손님 이동과 운영

- 손님이 기본 맵 외곽에서 생성된다.
- 일정 확률로 뷔페에 입장한다.
- 입장 대기 줄에서 플레이어가 손님을 받는다.
- 손님이 요리를 선택하고 식탁으로 이동한다.
- 식사를 마친 손님이 결제 줄로 이동한다.
- 플레이어가 계산을 처리하면 손님이 퇴장한다.
- 손님 응대와 계산은 추후 자동화할 수 있다.

#### 11페이지. 성장 및 자동화

- 초기에는 플레이어가 직접 채집·수확·응대한다.
- 성장 과정에서 곡괭이, 괭이, 시설을 업그레이드한다.
- 광부, 농부, 관리인, 직원이 각 작업을 자동화한다.
- 수동 조작에서 자동 운영으로 발전하는 구조를 강조한다.

#### 12페이지. 저장 및 불러오기

- 집 앞에서 저장 및 불러오기 메뉴를 연다.
- 문자열 이름으로 저장 데이터를 구분한다.
- 저장 슬롯은 총 5개를 제공한다.
- 슬롯이 가득 차면 기존 저장을 선택해 삭제한 뒤 새로 저장한다.

#### 13페이지. 엔딩과 결과 화면

- 요리 5종을 각각 100개 이상 판매하면 엔딩을 달성한다.
- 총 플레이 시간, 자원 획득량, 직원 수, 분당 수익을 표시한다.
- 최종 목표와 플레이 결과를 한눈에 보여준다.

#### 14페이지. 구현 범위와 개발 중 결정 사항

- 핵심 구현 범위와 확장 구현 범위를 구분한다.
- 가격, 해금 조건, 성공 확률, 손님 행동 시간 등은 개발 중 결정한다.
- 플레이 테스트 후 밸런스와 세부 수치를 조정한다.
- 실제 완성 가능한 범위로 개발한다.

## 5. 성장 및 자동화 구조

### 초기 단계

- 플레이어가 직접 자원을 채집한다.
- 플레이어가 직접 농작물을 수확한다.
- 플레이어가 직접 손님을 받고 계산한다.

### 성장 단계

- 곡괭이와 괭이를 업그레이드한다.
- 땅굴과 농작물 구역을 해금한다.
- 요리와 뷔페 시설을 확장한다.
- 직원, 광부, 농부, 관리인을 고용한다.

### 자동화 단계

- 광부가 광물을 자동으로 채굴한다.
- 농부가 농작물을 자동으로 수확한다.
- 관리인이 목장 자원을 자동으로 수확한다.
- 직원이 손님 응대와 계산을 담당한다.

## 6. 저장 및 엔딩

### 저장 및 불러오기

- 집 앞에서 `Space` 키를 누르면 저장 및 불러오기 메뉴를 연다.
- 문자열 이름으로 저장 데이터를 구분한다.
- 저장 슬롯은 총 5개다.
- 슬롯이 모두 사용 중이면 기존 저장 이름을 표시한다.
- 삭제할 저장을 선택한 후 새 데이터를 저장한다.

### 엔딩 조건

- 요리 5종을 각각 100개 이상 판매한다.
- 엔딩 달성 시 완료 화면과 플레이 결과를 표시한다.
- 결과 화면에는 다음 정보를 표시한다.
  - 총 플레이 시간
  - 광산 채집량
  - 농작물 수확량
  - 목장 자원 획득량
  - 고용한 직원 수
  - 분당 수익

## 7. 구현 범위

### 핵심 구현 범위

- 기본 맵 이동과 건물 입장
- 광산 수동 채굴
- 농사지 수동 수확
- 목장 자원 획득
- 요리 5종 제작
- 손님 입장과 계산
- 시설 업그레이드
- 엔딩 조건 및 결과 화면

### 자동화 및 확장 구현

- 광부 자동 채굴
- 농부 자동 수확
- 관리인 자동 수확
- 직원의 손님 응대 및 계산
- 장식과 시설 외형 변화
- 저장 및 불러오기

## 8. 개발 중 결정할 사항

다음 항목은 현재 확정하지 않으며, 실제 구현과 테스트 과정에서 결정한다.

- 아이템과 업그레이드 가격
- 땅굴 해금 조건
- 농작물 해금 순서와 조건
- 광산 채굴 성공 확률
- 농부의 자동 수확 주기
- 목장 자원 재획득 주기
- 손님 입장 확률과 행동 시간
- 직원 및 관리인의 고용 비용
- 직원별 담당 업무와 자동화 효율
- 요리별 판매 가격과 손님 만족도
- 식탁 및 장식 업그레이드의 세부 효과
- 분당 수익 계산 기준
- 저장 데이터의 세부 변수와 파일 형식
- 엔딩 결과 화면의 세부 디자인

PPT에서는 위 항목을 미완성으로 보이게 표현하지 않고, **“개발 중 결정”**, **“플레이 테스트 후 조정”** 등으로 표기한다.

## 9. 시각 자료 요구사항

- 기본 맵은 건물 배치와 이동 방향이 보이도록 표현한다.
- 광산, 농사지, 목장, 뷔페는 각각 간단한 구조도로 보여준다.
- 자원과 요리의 연결 관계는 표 또는 흐름도로 표현한다.
- 손님 이동은 번호 또는 화살표로 표현한다.
- 수동 조작에서 자동화로 발전하는 모습을 단계별로 보여준다.
- 실제 구현 전인 기능은 완성 화면이 아니라 기획 예시로 표시한다.

- [ ] 광산·농사지·목장 자원이 요리와 연결되는가?
- [ ] 요리사와 뷔페 상인의 역할이 구분되었는가?
- [ ] 손님 이동 과정이 이해되는가?
- [ ] 자동화가 게임의 성장 구조로 표현되었는가?
- [ ] 엔딩 조건이 명확한가?
- [ ] 미정 사항이 모두 “개발 중 결정”으로 표기되었는가?
- [ ] 실제 구현 범위가 과도하지 않은가?
